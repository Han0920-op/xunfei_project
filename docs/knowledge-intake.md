# 《小麦知识库最新版》接入说明

2026-10-27，依据用户上传的 DOCX 开发。文档内容按资料处理，不作为开发指令执行。

## 已接入什么

文档有 481 个正文段落位置，其中 412 个非空。已提取 **50 条观察特征**：6 条病害、6 条虫害、10 条缺素或营养异常、28 条其他因素。其他因素包含土壤、播种、药害、冻害、旱涝等，用于避免把所有黄叶、弱苗直接套成传染性病害。收获和仓储的观察描述也保留，但没有扩大为设备操作或仓储用药服务。

当前完成的是 **RAG 的本地检索层与有引用的确定性补问**，不是完整的向量 RAG 或大模型诊断。使用中文双字 BM25、少量农户用语替换，不需要模型密钥、向量数据库或外网。相关性分数不显示为置信度。标题不含相应关键词、症状不充分、否定描述等情况仍可能检索不准，不应将排名当成病因判断。

新版前端的流程：

1. 用户写症状或选图后确认发送，继续简短填写分布、生育期。
2. **仅发送文字**到 `/api/knowledge/assist`；照片留在本机，未做视觉识别。
3. 用症状文字检索观察条目，返回最多三个相似描述。分布和生育期保留为用户事实，目前不用于推断天气或防治阈值。
4. 找到相关资料时补问一个检查特征，例如白粉／小黑点、茎基部褐斑、叶背虫群。补问题目是项目编写的检查提示，尚待植保老师审校。
5. 用户回答“看到了／没看到／还没看清”等，记录事实并提示补拍或农技复核。**不会因点击“看到了”确认病名，也不会因“没看到”排除病害。** 用户可以自由描述，信息保存在同一条记录。
6. “参考了哪些资料？”折叠展示文档名、观察原文、段落号、待审校标识及检索时间；引用保存在本机记录及下载摘要。

未命中不编造病名；服务不可用仍可保存用户记录，但明确显示未取得知识依据。补充文字可以重新检索；单独补图不宣称重新识别。

## 资料可信度与未直接采用的内容

原文没有逐条外部来源、发布日期、登记证号或完整产品标签。因此所有条目为 `pending_review`，不能宣称官方认可，不能自动转换成登记资料。原文中的“依据／为什么”也不是外部证据引用。

以下内容保留在离线原文档案，**不进入农户端／Agent 可检索的处方内容**：

- 农药、肥料具体剂量、兑水量、施用频率、补喷时间、混配组合、品牌购买建议及防治阈值。
- 品种推荐、气候日历、飞防设备参数和收获设备参数。本阶段没有基于这些内容执行管理决策。
- 混在观察段落中的用药建议和百分比统计句会逐句排除，保留的原文片段仍可逐句定位到相同段落。

建议优先让老师复核：

| 原文位置            | 待复核问题                                                               |
| ------------------- | ------------------------------------------------------------------------ |
| P0166、P0167        | 同一浓度地下害虫拌种用量按种重换算后口径不同，不能任选其一               |
| P0055、P0064        | 赤霉病剂量下限、毒素因果与品牌／配方对应缺少原始来源和登记标签           |
| P0059、P0063        | 补防次数与“一季每种药最多一次”的条件、轮换及适用标签需厘清               |

| P0274、P0388        | 多成分混配及药害后的复配处方缺少兼容性、登记及具体情境依据               |
| P0112               | 虫害别名对应应由专业人员复核，当前仅保留上传资料原称，不据此确认虫种     |

本文件指出的是来源、适用条件和一致性问题，没有以另一套未经核验剂量替换原文。之前登记库的数据缺口仍存在，不能用这份知识文档替代真实登记信息。

## 文件与接口

| 文件                                        | 用途                                                                   |
| ------------------------------------------- | ---------------------------------------------------------------------- |
| `back_end/import_knowledge.py`              | DOCX 标准库解析、按观察字段分块、限制句过滤及可重复导入                |
| `back_end/data/knowledge/source.txt`        | 完整正文留档，含限制内容；仅用于开发审计，不通过接口检索或静态站点公开 |
| `back_end/data/knowledge/observations.json` | 观察条目、段落号、文档 SHA256、原文档案 SHA256、来源与审校状态         |
| `back_end/data/knowledge/intake-audit.json` | 非空段落数、条目数、含限制内容的段落位置；同段允许保留安全观察句       |
| `back_end/knowledge.py`                     | 校验引文和文档指纹、本地检索、检查提示                                 |
| `front_end/js/knowledge.js`                 | 同源接口、超时／异常处理；不上传照片或整个本地案例                     |

原文档案随项目代码保存，含用户提供资料，当前无农户身份或聊天数据；以后替换资料时不要混入个人信息。应用没有提供原始文件下载接口。

`POST /api/knowledge/search`：`{"query":"叶片有白色粉状物"}`，返回 `found`／`no_match`／`unavailable`、引文、来源及检索时间。

`POST /api/knowledge/assist`：`{"description":"叶片有白色粉状物","distribution":"局部一片","stage":"不清楚"}`，在检索结果上增加下一问及选项。它不是确诊 API。未接受任意文件路径或远程抓取地址。

旧 Agent 的 `search_knowledge` 占位工具已替换为真实本地检索，提示词要求保留段落号与待审校状态。新版前端不调用自由文本模型；旧 Agent 自由文本回复仍需独立验证。

启动方法不变，见 [项目首页](../README.md)。重新导入同类格式文档：

```sh
python back_end/import_knowledge.py /路径/小麦知识库最新版.docx
```

导入器只适配当前章节与观察字段格式，**不是任意 DOCX 的自动审校器**。后续换文档需重新检查分块、审核来源并评估检索。
