# 天气预警：网页演示与真实来源边界

更新：2026-11-02，版本 `2026.11.02.weather`。

本轮按用户补充要求完成：**只做网页内提醒和可展示的防护建议，不接后台推送、微信或短信**。既有其他提醒的桌面通知设置保留，新增天气提醒不调用系统桌面通知。

## 展示方法

1. 打开“提醒→天气预警”，或直接访问 `weather-alerts.html`。
2. 有地区订阅时可选择该地区；没有订阅时使用明确的“示例地区”，不假设真实所在地。
3. 点击“演示暴雨橙色提醒”“演示大风黄色提醒”“演示寒潮蓝色提醒”或“演示霜冻橙色提醒”，立即弹出网页提醒。
4. 可选择发布、升级、解除三个展示阶段；查看防护和复查建议，再点击“知道了”。
5. 演示卡、弹窗、标题及正文始终标注“演示／非真实预警”。刷新后演示结果消失，不进入未读消息、真实预警列表、案例事实、RAG或模型上下文。

建议展示话术：“这里人工触发一个天气情景，演示智麦如何提醒和帮助安排防护；这不是当地正在发生的官方预警。”

建议涵盖先保证人员安全、安全条件下检查排水和工具、天气好转后观察积水/倒伏/新叶并补图。均为一般防护与复查方向，未经过独立本地农技审校；不依据预警统一安排农药、剂量、施肥或灌溉，也不把气象风险当作已经发生病害。

## 真实来源已完成的代码

- 公共源读取路径固定为中国气象局天气网站 `https://weather.cma.cn/api/map/alarm`，不接受用户任意远程URL。禁止重定向，限制超时、大小，不记录原始异常、请求凭据或来源正文。
- 适配标准CAP公开实际预警及具有明确字段的JSON记录。只有发布机构、类别、级别、行政范围、发布时间、生效时间和有效期可以核对时才能进入真实数据流程。未识别的数组列、HTML页面、缺少有效期或范围的数据不猜测解释。
- 源不明确或不可用时不从大模型、普通天气预报或演示数据回填“官方预警”。当前没有记录也不意味着当地没有风险。
- 时间与地区校验、类型/级别筛选、跨订阅去重、静默、频次上限、更新/升级/解除已有代码与替身测试。解除需要来源明确的取消消息，列表消失不代表解除。已更新、解除或过期记录不再作为旧预警重复弹出。
- 地区订阅中天气预警单独开启，旧订阅默认不开启。可只订阅天气、不选病虫害。城市可识别时采用现有城市编码；不能识别时需用户核对六位行政区编码。省份与编码不一致会拒绝保存，不把任意县预警泛化成另一个城市发生灾害。
- 用户可选择橙红首次发布/升级越过静默及次数上限；同级更新不无限越过限制。不开此选项时遵循原静默及次数设置。
- 后端保持运行时，启用天气订阅才定时读取来源，默认10分钟一次，独立线程不阻塞原有聊天及普通提醒。网页打开后全站轮询并显示站内消息。**不支持关闭网页后的主动送达。**
- 聊天背景只读取当前匹配、来源未过期的真实记录；演示永不进入该背景。历史报告保留当时引用，不能替代最新预警。

## 尚未完成真实联调的部分

当前云环境网络允许列表不含 `weather.cma.cn`，实际连接失败，见[连接记录](research/weather-warning-connectivity.json)。因此，本轮**没有获取真实官方预警，也未验证该公共路径当前返回的数据结构是否适配**。网页会显示未检查、无法读取或数据尚不能确认，不显示虚假的“实时监测正常”。该公共网页接口的持续可用性和使用条件也需在实际部署时确认。

这是可以演示的前端提醒功能，以及已有校验与通知代码；不能宣称已经正式上线可依赖的气象灾害预警服务。正式接入需在可访问官方数据的部署环境中核验接口结构、时间、辖区、更新和解除语义，必要时使用经授权的官方数据接口。不要为了演示将替身数据导入真实来源缓存。

## 数据、接口与验证

新增表位于原有不提交Git的 `back_end/data/local/personal.db`：weather_warning_events、weather_warning_latest、weather_warning_deliveries、weather_warning_meta。演示接口不写这些表或entries通知记录；旧农药、任务和案例不迁移清空。

- `GET /api/weather-alerts/status`：当前身份匹配的真实记录、公开源读取状态和可用演示类型。
- `POST /api/weather-alerts/demo`：当前身份触发演示，写操作防跨站请求头仍必需；不能指定别人订阅。
- `weather_alerts.py`：规则、来源适配、生命周期、一般防护建议及调度。
- `test_weather_alerts.py`：隔离演示、权限、地区、有效期、静默、频控、重复、更新、解除与失败保护，全部用明确标注的合成数据。
- `front_end/tests/weather_alerts_smoke.py`：真实HTTP和浏览器，验证四类弹窗、发布/升级/解除、天气单独订阅、指导展示、刷新清除、无真实数据污染及站内通知流程；不调用真实灾害接口或模型。

运行方式与原项目一致，更新代码后重启后端并强制刷新浏览器。无需新增密钥或依赖。
