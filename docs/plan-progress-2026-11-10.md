# 排查方案执行与复查跟进

版本：`2026.11.10.plan-progress`

## 用户可见变化

- 每个排查步骤可以手动勾选完成或取消完成，自动保存到服务器。
- 方案列表与详情显示“已完成 N / M 项”，状态分为待执行、进行中、步骤已完成。
- 保存失败时恢复上次已确认的显示，提供重试入口；连接中断或超时不会冒充保存成功。
- 两个页面同时修改时，旧版本写入会被拒绝，页面读取最新状态后提示用户再次操作。
- 已结束的案例仍可查看方案；重新打开案例前不能更改步骤进度。
- 从方案进入“记录复查结果”可回到原案例；“安排案例复查”直接打开关联该案例的提醒表单，用户选择时间并确认后才创建提醒。
- 修正方案页面的浏览器标题和未启用 JavaScript 时的提示。

## 数据与接口

新增 `PATCH /api/plans/{id}/steps/{number}`，仅接受严格布尔值 `completed` 与整数 `revision`。延续当前浏览器身份隔离及 `X-Zhimai-Personal: 1` 写入校验。

写入在事务中完成，核对案例所有者、归档状态、方案版本和步骤编号；只更新相应步骤、完成时间、更新时间及版本。重复设置相同值不会增加版本。旧方案缺少版本号时按 0 处理，不需要数据库迁移。

勾选只代表用户报告已执行该排查事项，不改变案例诊断、农药核对状态、已确认事实或提醒，也不会自动结束案例。提醒创建仍经过原有表单确认和时间校验。

## 验证

- 293 项后端测试通过，包含并发写入、旧版本冲突、取消完成、身份隔离、字段约束、已结束与已删除案例。
- 16 项相关浏览器测试通过：5 项方案跟进测试，加上 11 项方案生成、提醒、农药库与案例回归。
- 浏览器覆盖刷新后恢复、保存失败回退与重试、断网提示、并发状态刷新、移动端布局和复查提醒绑定原案例。
- 使用隔离数据库和本地真实 API；没有写入用户资料或调用付费模型。

## 演示步骤

1. 在原案例生成并保存排查方案，打开详情。
2. 根据实际演示操作勾选一项，例如“补拍关键部位”；刷新，展示进度仍保留。
3. 点击“安排案例复查”，展示自动带入的原案例，选择未来时间并确认。
4. 点击“记录复查结果”，在原案例中填写变化与真实措施。
5. 从“我的记录 → 执行方案”再次查看执行进度。

更新后重启本机后端，并刷新页面。旧方案可直接使用新增的进度功能，无需重新生成。
