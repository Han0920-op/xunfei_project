# 登记核对：官方公告资料接入 V2

2026-10-27：已将用户授权接入的20条真实公告记录编译为运行时登记库，默认供前端及 Agent 工具查询。包括1个小麦赤霉病制剂、10个其他作物制剂、9个原药／母药。**它们证明公告时的登记范围，不证明当前登记有效或现在可以施药。**

## 运行与体验

按 [项目首页](../README.md) 启动后端，从同一地址打开前端，不需要模型密钥即可核对。默认读取 `back_end/data/pesticides/official-announcements.json`，不必填写环境变量。

- `PESTICIDE_CATALOG_PATH` 未设置或留空：使用内置公告资料。
- 显式指定其他文件：只读取该文件，文件损坏或路径无效时返回 `source_unavailable`，不会回退成旧结果。
- 仍支持旧 V1 人工快照，以便既有部署兼容；新资料使用 V2。

页面点“手里的药，能不能用？”，输入登记号，再选择对象：

| 输入                 | 预期行为                                                 |
| -------------------- | -------------------------------------------------------- |
| PD20250010／赤霉病   | 公告的小麦与对象相符，但当前有效性待核实，暂不能据此施药 |
| PD20250010／白粉病   | 公告中同一作物对应的防治对象不符，不据此用于当前情况     |
| PD20250008／白粉病   | 公告登记为黄瓜白粉病，不能套用于小麦                     |
| PD20250005／赤霉病   | 母药用于制剂加工，不能直接用于田间                       |
| PD20250010／还没确定 | 先确认防治对象，不把登记信息当作诊断                     |
| 未收录号码           | 本地未收录，不表示官方没有登记                           |

可以折叠查看标签注意事项、版本、来源链接与查询时间；核对记录保存在原来同一条对话。未经核实的剂量、施用次数、兑水量和安全间隔期不会进入用药回答。完整公告版标签仍可通过原始来源打开，但不冒充最新有效标签。

## 判断边界

接口 `POST /api/pesticides/check` 输入：

```json
{ "registration_number": "PD20250010", "crop": "小麦", "target": "赤霉病" }
```

输入格式仍限 PD／EX／LS 加6—12位半角数字，格式错误返回422。数据状态返回200，并将三类结论分开：

| 字段                     | 解释                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------- |
| `scope_match`            | `match`／`mismatch`／`unknown`／`not_applicable`，仅说明资料中的作物、对象成对匹配情况 |
| `use_decision`           | `hold_for_verification` 或 `do_not_apply_from_this_record`，不能凭此记录施药           |
| `recommendation_allowed` | 当前版本始终为 false；未完成标签、田间条件和审校要求，没有施药许可                     |
| `reason_codes`           | 当前状态未核实、到期日缺失、对象不明、作物不符、原药母药等原因                         |
| `next_steps`             | 农户下一步应核对什么                                                                   |
| `label_reference`        | 公告版标签注意事项、原始链接、定位及待审校标识；不返回制剂用量与技术用量处方           |

兼容状态字段：

| status                 | 含义                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------ |
| `source_unavailable`   | 显式配置错误、资料损坏或校验失败                                                     |
| `not_in_local_catalog` | 本地未收录，不能推断官方不存在                                                       |
| `needs_review`         | 公告范围相符但当前状态／有效期不明，或对象不明、复核时间异常                         |
| `mismatch`             | 资料中作物或成对对象不符、原药母药不可直接使用，或快照显示撤销／过期                 |
| `fields_match`         | 其他人工快照的字段相符，也不等于已判断需要打药或推荐用药；本批20条公告不会进入此状态 |

缺少当前状态不会掩盖已知的范围不匹配或原药母药限制。对于历史范围只说“本资料未列出／不据此使用”，不声称它就是当前官方范围。每条公告记录都保留 `status=unknown`、`valid_until=null`、`current_checked_on=null`。

复核期限仍为30天，是项目检查资料时效的要求，不是法定期限。公告转录日期不等于当前登记查询日期，不能通过刷新日期把公告升级为现时有效登记。标签“质量保证期”不当作登记有效期；缺安全间隔期不视为0天。

## 数据与导入

- 原始研究记录：[公开资料报告](research/pesticide-registration-2026-10-27.md)及同目录JSON，保留整理时事实，不直接作为运行时配置。
- 编译输出：`back_end/data/pesticides/official-announcements.json`，V2结构，不含任何假登记号。
- 来源：农业农村部第880、910、1019号公告及登记表、核准标签。允许的官方来源域名包括 `www.moa.gov.cn` 和原有登记网站域名；域名校验本身不能证明内容正确。
- `import_registrations.py` 验证原始附件SHA256和字节数、登记用途、资料状态及来源关联，先整批校验再原子写入；不自动提升有效状态或农技审校状态。
- 含量字段保留菌株和数值之间的分隔，例如 `C17271 5亿CFU/克`，避免显示成一个连在一起的数字。

需要重新生成时（附件目录为下载资料包中的“官方附件”）：

```sh
python back_end/import_registrations.py \
  docs/research/pesticide-registration-2026-10-27.json \
  --evidence-dir /路径/官方附件
python back_end/validate_pesticides.py back_end/data/pesticides/official-announcements.json
```

V2中，`source.evidence_kind=approval_announcement` 禁止填写已有效状态、登记到期日或当前查询日期；要补齐当前状态，需要另取得可靠的当前登记资料，采用 `current_registry_snapshot`，并记录独立的 `current_checked_on`。不能只修改本批数据的状态或以产品储存期限代替。

## Agent 与模型

新版前端直接调用确定性核对接口。旧 Agent 的 `check_pesticide` 使用同一个判断器；**一旦调用该工具，结果通过程序直接格式化，不再让模型二次改写为“可以使用”**。调用前的模型自由文本对话仍不是受程序核验的用药结论，实际核对应走登记接口或工具。

该阶段不自动推荐其他药，不提供混配或剂量计算；没有接入包装OCR、最新官方状态或气象施药规则。知识库的症状检索不能代替登记依据。
