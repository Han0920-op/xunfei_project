# 文字模型连接与模型名称自检

截图中的“后端无法连接文字模型服务”对应请求连接异常，不代表已收到“模型不存在”的 HTTP 响应。此前此类错误包含代理、HTTPS 证书、地址格式和普通网络连接等多种情况；现在单独识别代理失败、证书失败和地址错误。

项目按 `DEEPSEEK_MODEL` 的实际配置发送模型名称，没有把它锁定为 `deepseek-chat`。模型目录可能更新，`deepseek-flash` 是否存在、完整 ID 是否带其他前后缀，均应查询当前 API，而不是凭显示名称猜测。旧文档和配置示例中的模型名只是历史示例。

## 使用

1. 在本机 `back_end/.env` 保留 `LLM_PROVIDER=deepseek`、自己的 `DEEPSEEK_API_KEY`，官方地址为 `DEEPSEEK_BASE_URL=https://api.deepseek.com`（不附加 `/chat/completions`）。不要提供密钥给维护人员。
2. 拉取本补丁后，在项目根目录双击 `check_model.bat`。它使用与启动器相同优先级的 Python 虚拟环境，读取现有配置，执行 `GET /models`，不调用生成接口、不上传图片、不修改环境变量或绕过代理。
3. 根据返回结果处理：

| status | 含义与下一步 |
| --- | --- |
| ok | 模型列表可访问，所选 ID 在列表中；仍需用最小文字问题验证生成接口 |
| model_not_listed | 连接及模型列表查询成功，核对 `available_models` 和供应商控制台中的完整 ID（目录可能不含全部模型） |
| model_proxy_failed | 检查后端所在电脑的代理是否运行、地址及端口是否正确 |
| model_tls_failed | 检查系统时间、可信证书和代理证书；不要关闭证书校验 |
| model_connection_failed / model_timeout | 检查网络、域名连接和服务状态 |
| model_auth_failed | 收到鉴权失败响应，核对同一服务的 Key 与授权 |
| model_endpoint_invalid | 核对 BASE_URL；404 也可能是该端点不支持 /models，需核对控制台 |
| model_not_configured | 没有读取到所选供应商的 Key |

`proxy_configured` 只报告该 URL 是否存在有效代理配置，不显示代理地址及凭证。HTTP 成功不代表生成接口参数、余额或速度已验证。

4. 保存配置，关闭旧智麦后端，再启动 `start.bat`。访问 `/api/agent/capabilities`，核对运行中的 `chat_provider` 和 `chat_model`，防止自检读取新配置而旧后端仍运行旧配置。
5. 先发送不含图片的“你好”，把文字接口与图片接口问题分开。仍失败时，可提供自检输出、页面诊断编号或服务端同编号的安全诊断日志；不提供 `.env`、密钥、原始供应商错误正文。

## 模型列表成功，但网页聊天仍失败

`GET /models` 返回 200 且模型在列表中，只证明该次请求成功，并不测试 `POST /chat/completions`、生成计费或 SSE 流。

更新代码后保留原来的 DeepSeek 配置和 `VISION_PROVIDER=xfyun`，关闭旧后端再运行 `start.bat`。双击根目录 **`check_chat.bat`**：

- 读取与应用相同的文字配置，先对照本机后端的版本、供应商和模型名称。
- 使用应用的流式 HTTP 实现，发送固定的短连接测试，不上传历史或照片、不调用工具、不修改配置。
- 流式成功后使用智麦真实答案解析器检查结果。流式失败时，如不是鉴权、计费、参数、代理、证书或限流等明确错误，再使用同一配置测试一次普通生成。
- 最多两次生成请求，可能产生模型费用；等待可能超过一分钟。诊断不自动重试，以保留第一次失败的证据。不关闭 TLS 校验，不绕过供应商请求的代理。
- 只输出状态、耗时、正文长度和允许公开的异常类型；不会输出 Key、代理地址、原始错误正文、模型正文或内部思考。

| 结果 | 可以说明什么 |
| --- | --- |
| `running_backend.status=model_config_differs` | 运行中后端与自检的模型选择不同，需核对启动环境并重启 |
| `stream.status=ok` 且 `answer_format=ok` | 这一次真实流式生成及答案解析通过；长上下文、图片与工具仍需另测 |
| `stream.http_status=200` 后超时或中断 | 已取得响应头，故障发生在等待或读取正文期间，不是完全未连接 |
| `stream` 失败、`nonstream.status=ok` | 普通生成可用，需检查流式传输和等待时间；也可能是短暂故障，不能直接断言代理有问题 |
| 两种生成都失败 | 根据具体 HTTP 状态与异常类型定位；模型列表成功不能代替生成验证 |
| `model_payment_required` / HTTP 402 | 生成请求要求付费或补充余额，去对应服务控制台检查 |
| `model_request_invalid` / HTTP 400 | 接口拒绝生成参数，需结合当前模型接口规范核对；不等于网络连接失败 |
| `answer_format_invalid` 且流式成功 | 生成接口已返回完整正文，但未通过本次答案格式验证 |

仅有 `proxy_configured=true` 不表示代理坏了。不要直接关闭代理或证书校验来掩盖故障。提供自检结果及网页新诊断编号即可，不必发送 `.env`。

如果排查后仍需使用星火，可以只修改 `LLM_PROVIDER=spark`、`VISION_PROVIDER=xfyun`，保留自己已经开通的 `SPARK_BASE_URL`、`SPARK_MODEL`、`SPARK_API_PASSWORD` 与图片配置。重启后同样运行 `check_chat.bat` 验证。程序不会因 DeepSeek 一次失败而悄悄更换供应商。

此补丁还修正了 requests 把底层读取超时包装成 ConnectionError 时的错误分类。现在按类型识别超时，不读取可能含凭证的异常字符串；已经输出正文后的超时仍不会自动重放回答。

## 通义千问文字＋视觉组合

希望不用讯飞图片服务时，可以在 **百炼开通文字及视觉模型，并创建对应地域的 API Key**，然后修改 `back_end/.env` 中同名项，避免重复配置：

```ini
LLM_PROVIDER=qwen
VISION_PROVIDER=qwen
DASHSCOPE_API_KEY=在本机填写百炼Key
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_MODEL=qwen-plus
QWEN_VISION_MODEL=qwen-vl-plus
QWEN_TEMPERATURE=0.3
QWEN_MAX_TOKENS=2048
VISION_MAX_TOKENS=800
MODEL_CONNECT_RETRIES=1
```

以上为中国内地服务地址和可配置的模型示例，模型 ID、开通状态、Key 与地址地域须以百炼控制台为准。文字负责对话决策、工具选择和整理答案；视觉只提取图片可见特征，再交给文字模型结合查询结果回答。DeepSeek 官方 Key 不能用于百炼；切换后不会暗中使用旧讯飞 Key。

保存后重启后端，核对 `/api/agent/capabilities` 的 `chat_provider`、`vision_provider` 都为 `qwen`。`configured=true` 只表示配置存在，不代表已经连通。`check_model.bat` 同样支持 Qwen 的模型目录查询；如果所选端点不支持 `/models`，应在控制台核对，并使用下面的实际对话步骤验证。

建议依次验收：

1. 无图发送“你好”，确认文字能够正常返回。
2. 上传真实的小麦照片，要求“只描述可见症状，信息不足请说明”，确认图片观察和文字回答都成功。
3. 请求查询相关资料，检查网页卡片能打开、答案能完成；搜索不可用时应明确说明，不编造来源。
4. 要求创建一次提醒，在提醒页核对记录，然后切回原会话继续交流。

## 重试范围

文字流在尚未输出内容时，针对连接失败、超时、429、5xx 最多重试一次。服务要求等待超过 2 秒或本轮剩余预算不足时直接返回明确错误。鉴权、代理、证书、请求格式错误不会重试；已经输出的内容不会重放。重试只包裹本次模型 HTTP 请求，不重新执行已完成的工具。现有整轮时间预算继续生效，默认 140 秒。

视觉服务本次新增兼容接入，没有自动重复图片请求。图片服务失败会明确提示；无法识图不会伪装为“作物正常”。这套机制减少短暂故障造成的失败，不能保证供应商永不超时，也不代表对供应商速度做过实测。
