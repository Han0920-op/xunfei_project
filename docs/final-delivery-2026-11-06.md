## 独立功能与数据流

1. **图片观察**：在`dialogue.py`细化逐株逐穗比较，关注局部漂白、绿色对照、穗轴变色、粉状覆盖/疱斑及拍摄局限。先观察再鉴别，保留成熟/干旱/损伤等其他解释；不把预设症状写成图片事实。模型及参数未擅自更换。
2. **联网搜索**：`web_search.py`固定访问Bing公开RSS，真实HTTP请求、连接/读取截止和大小限制；校验URL，去重并过滤与病害关键词/指定站点不符的结果。搜索结果仅是网页线索，不能证明官方登记、当前预警或药剂适用。`tool_start/tool_result/tool_error`携带`case_id/turn_id/call_id`。`search-ui.js`按事件显示状态与实际链接，重复事件不重复渲染，错误/中断停止加载；完成结果随会话保存，刷新可再查看。未完成会话刷新不会自动重放搜索。
3. **标题**：`case_titles.py`校验首轮模型生成的6—15字标题，病名不作为确诊。复用同一次回答，在`content`之前返回可选`title`，成功存储后才发布`case_title`；无需第二次模型请求。首次临时“新诊断”，缺失/异常标题回退，旧案例/手动标题不批量覆盖，标题失败不影响聊天。`response_stream.py`保持原有检查字段与流式正文约束。
4. **执行方案**：`save_execution_plan`由模型根据当前案例选择结构化排查步骤。`execution_plans.py`以Pydantic验证，读取当前身份实际案例与用户描述、已存检索来源；未知字段标待确认。模型只选择补图、观察、现场核对、标签核对、农技复核、复查步骤，具体操作由受限模板提供，防止将未经核验的剂量/混配写成行动。保存成功后提供详情入口。`GET /api/plans`及`GET /api/plans/{id}`按身份隔离；前端不能指定owner。`plans.html`/`plans.js`提供列表、完整详情和返回原案例。当前状态为待执行，勾选、状态修改、PDF属于未实现的P2。
5. **对话入库**：同时交付上一轮已开发但未提交的农药自动入库；详见`personal-weather.md`。本轮没有丢弃原工作区修改。

## 数据与兼容

沿用`back_end/data/local/personal.db`。新增`execution_plans`和`case_titles`表均为`CREATE TABLE IF NOT EXISTS`，不改旧表列或重建数据库。同用户、案例、请求编号保存方案幂等；删除案例连同关联方案删除。用户身份凭据只在服务端用于归属校验，不返回原始凭据。上线前备份本机数据库；更新后重启后端并强制刷新。版本`2026.11.06.delivery`，SSE协议保持v2，新增事件为兼容扩展。

## 真实图片对比方案

准备同一批经授权且由农技人员标注的照片：穗部局部异常、锈病样斑、白色覆盖、非病害黄化、正常植株、模糊图各至少3张。记录拍摄部位/日期/地区（未知就留空），每张给可见特征清单与不应出现的特征。用同一图片处理、同一问题和相同上下文分别运行原提示与新提示，记录漏掉可见异常、编造不可见特征、合理候选与关键追问、耗时/失败。由人工盲评，不让同一模型自评代替标注。若仍不足，再对候选视觉模型做相同输入对比；在成本、异常召回和幻觉指标确认前不更换生产模型。
