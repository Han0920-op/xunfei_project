## 产品目标与目前位置

围绕一个具体问题形成闭环：**上传异常照片 → 智麦按需检查和检索 → 核对手里的药 → 记录实际处理 → 到时提醒复查 → 带新照片继续对话**。个人农药库保存用户持有的产品资料；定时任务让约定的后续事项真正执行。

## 我的农药库：首版范围

### 农户怎么用

1. 在对话中拍清标签、输入登记号，或从“我的农药库”添加产品。
2. 智麦提取能辨认的名称、登记号、成分、含量、剂型等，显示一张简短确认卡；不清楚的字段留空或标待确认。
3. 农户纠正并确认“保存到我的农药库”。上传照片、OCR成功或登记范围相符都不自动代表入库成功。
4. 后续对话中，智麦在涉及已有药品时按需查询，说明使用了哪条个人资料；保存成功不等于该药适用于当前问题。

### 保存内容与判断边界

- 基础资料：用户可辨认的产品名称/备注，登记号、成分、含量、剂型、厂家等已确认字段，标签照片引用和来源对话。
- 对每个识别字段保留来源及确认状态；登记核对结果另存来源、查询时间、范围与当前有效性状态，不由用户确认标签来提升为官方核验通过。
- 产品生产/到期信息仅在可读或用户明确填写时记录；**产品保质期与农药登记有效期分别保存**，未知不推算。
- 库存首版只需“持有／已用完／移除”等简单操作；数量、批次、成本与自动扣库存暂缓。登记号相同但包装/批次不同，提示关联而不擅自覆盖标签与到期信息。
- 个人药品属于用户资料，公共登记资料属于核验依据，症状知识属于检索参考，三者分别保存；不把用户上传包装自动加入公共RAG知识库。
- 读取已有药品时，先核对防治对象是否明确，再使用登记工具检查；资料不足、范围不符、产品过期、原药/母药等状态须保留。不能因为用户持有某种药就推荐使用，不能靠库存推导混配或剂量。
- “登记核对过”不等于“已用过”；实际施药时间与处理措施仍由农户按事实记录。

### 验收案例

- 模糊标签不会猜号码或悄悄保存；允许手动保存已知部分为待核实资料。
- 农户修正识别号码后，保存和后续查询均使用修正值；确认保存只生成一条记录，重复点击不重复新增。
- 新建对话仍可找到该用户保存的产品；不把整库每轮塞进模型上下文；其他用户不能读取或修改。
- 未收录号码仍能保留个人药品资料，但清楚显示未完成登记核验，不升级为可用结论。
- 标签照片、产品到期时间和登记状态能够单独查看/更新；用户可移除，后续查询不继续使用已移除条目。

## 定时任务：先提醒，再后台工具执行

### P2：一次性提醒

首版支持复查拍照、田间检查、核对标签等事项。例如：农户说“明天早上8点提醒我补拍黄叶”，智麦显示任务事项、**明确的年月日和时间**、通知方式及关联对话，确认后创建。

- 对话与“我的记录”都可新增、查看、改期、暂停/取消任务；修改后只按新时间执行，取消后不再触发。
- 时间含糊如“过几天”“晚点”时补一个关键问题；不猜小时。默认按北京时间 `Asia/Shanghai` 展示并明确标注，服务端以UTC保存时间和原时区。
- 到期后通知包含一句具体事项和“继续这次问题”的入口；查看通知不等于任务已完成，完成操作单独记录。
- 智麦可以建议复查时间或生成草案；没有确认的建议不是已创建任务。只有持久化成功后才回复“已设好”。不自动安排重复喷药或执行农机操作。

### 真正通知农户的实现门槛

不能依靠网页里的 `setTimeout` 实现定时提醒。当前本机保存复查日期的能力保留，并明确显示它尚不具备主动通知。

1. 后端持久保存任务、所属用户、触发时间、状态、关联问题和执行记录；独立调度器或后台工作进程扫描到期事项，进程重启后恢复。
2. 先接通站内通知：到期记录确实生成，离线时再次打开可见待办。但这一项单独完成只能叫“站内待办”，不能声称关闭页面也会提醒。
3. 首个主动触达渠道计划采用 **Web Push**：HTTPS、浏览器通知许可、订阅信息和服务端推送配置齐备后验证。适配目标手机/浏览器；不支持或拒绝授权时显示仅站内待办，不显示“可后台通知”。短信/微信留待另行接入。
4. 区分任务到期、执行成功、推送服务接受、投递失败和用户已读；服务接受不能冒充农户已收到或已完成。
5. 支持重启恢复、执行幂等和重试去重；修改/取消与调度并发时检查任务版本。错过的提醒按原时间列为逾期事项，不当作新任务集中轰炸用户。

P2完成需要验证一个实际主动通知渠道；仅保存日期、显示假通知或前端演示不计为定时提醒已交付。移动系统和浏览器可能限制后台通知，必须说明实测支持范围。

### P3：定时智能体任务

在一次性提醒稳定后，增加经用户确认的每日/每周周期任务。例如“每天早上8点查郑州天气，告诉我今天田间检查需要注意什么”。

- 用户确认地点、执行时间/周期、任务内容和通知方式后启用；后台可调用真实天气、审校资料及相关个人记录，产出简短结果。
- 执行时重新查询有时效的数据，不使用创建任务那天的天气；失败如实记录，不能用模拟天气填补。
- 任务种类、频率和运行时间受限，先限定天气查询/检查提醒，不直接执行任意模型生成的代码或全量长对话。
- 每次执行有独立结果/失败原因，可回看、暂停和取消；周期任务变更不会重复注册或在旧时间再次触发。
- 天气变化只支持检查提示，不自动确诊、决定打药或生成重复用药日程；需要防治决策时回到对话核实。

### 验收案例

- 明天8点能落为正确的年月日与时区；跨天、月底和改期场景没有日期偏移。
- 服务器重启后仍能触发；重复扫描不重复生成同一次执行记录；任务取消/改期在调度时生效。
- 目标浏览器不打开项目页面时，已授权用户能收到实际推送；拒绝权限/不支持时正确降级，不能伪报成功。
- 点击通知回到对应问题，补图复查可以延续原上下文；任务取消和完成状态分别可见。
- 周期天气任务每次读取当天新数据，失败不编造；与其他用户的任务、药品和对话隔离。

## 页面与架构衔接

保持首屏直接拍照/说话，主入口仍以“问智麦／我的记录”为主。在“我的记录”内增加 **“我的农药库”和“待办提醒”两个轻量入口/板块**，各自进入简短列表与详情，不恢复地块资料、多栏工作台或复杂统计页。

对话只在合适时展示“保存这瓶药”“设置复查提醒”等小卡片；药品详情可“带着这瓶药问智麦”，通知可“回来复查”。农户不必先建药品档案或任务才能使用诊断。

后续开发分工与依赖：

- **后端基础**：为个人资料和任务建立服务端用户/会话归属与访问控制，不信任模型或客户端随意指定的用户ID；服务端持久化才支撑跨对话读取、关闭页面后调度。保留并显式迁移用户选择同步的本地旧记录，不覆盖现有存储。
- **药品工具（计划新增）**：查询本人药品、准备入库草案；写入与编辑由用户确认后的接口执行并返回持久化结果，不把模型一句“已保存”当成功。
- **任务工具（计划新增）**：准备任务草案、查询本人任务；确认/改期/取消由后端校验时间、身份和状态后执行。后台工作进程只运行已确认且未暂停/取消的任务。
- **前端**：确认卡、两个轻量板块、提醒渠道状态与返回原对话的入口；维持流式回复和失败输入保护，不把调度状态等内部字段变成农户必须理解的表单。
- **验证**：覆盖确认/未确认、重复点击、登记服务失败、药品修改、用户隔离、时区、重启、去重、通知拒绝和取消竞态；并做一次真实手机端闭环。

上述均为后续开发项；当前可调用工具仍只有 `get_weather`、`search_knowledge`、`check_pesticide`，图片理解仍在新照片发送后自动执行。

## 下一开发周期的明确任务

1. 交付P0现有修正并完成真实联调，建立首字/总耗时与典型图片问题的基线。
2. 实现个人资料归属和药品最小数据模型，先跑通“标签→用户确认→保存→新对话读取”的P1闭环。
3. 完成P1后实现一次性复查提醒的服务端持久化、调度与真实推送，验收P2；周期工具任务留给P3。

先让用户能保存一瓶药、成功约一次复查，再逐步扩展，不同时建设完整库存系统、全作物知识库或全流程农事管理。
