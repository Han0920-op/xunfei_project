# 智麦五项能力：本轮交付与验收

更新于2026-11-01。以用户提供的《智麦五大特色能力开发参考文档_无地块版》及用户指定的三步顺序为依据。推荐框架不是强制迁移要求；本轮延续已有FastAPI、手工ReAct循环与SQLite事务，未引入地块、面积、地图或作物季管理。

## 第一步：案例基础与按需追问

- 一次成功咨询作为同一案例保存用户描述、视觉初步观察、模型候选原因、生育期、缺失信息、来源引用及已确认措施。结构化研判通过 `record_case_assessment` 工具暂存，仅在回答成功完成后与对话一并提交。失败响应不写入半条诊断。
- 进度为收集证据、待补充信息、初步研判、复查跟进、需农技复核、已结束观察。模型推测不是确诊；关闭案例不等于治愈。每轮只收集1至2个关键缺项，三轮仍不足则标记复核、停止继续追问的工具分支。
- 新照片保存为1600像素内JPEG压缩副本，移除EXIF/定位信息，通过身份校验的私有接口读取，不放入公开uploads目录。原始照片不入库。每案例最多100张，用户删除案例时连同照片、事件、报告、事实与关联任务删除。
- 旧照片不会批量上传。跨设备用恢复码找回身份后，可读取新保存的案例照片；旧本机照片仍需原设备提供。
- “我的记录→管理长期记忆与服务端案例→案例”可查看进度、症状、候选原因、缺项、照片、事件与已确认事实；聊天也有直接入口。

## 第二步：有依据的报告与案例复查

- `search_agri_guidelines` 仅检索有效且地区相符、已整理适用元数据的官方观察资料；保留标题、发布日期、地区、适用条件、原文URL、内容哈希、获取时间、整理状态和农技审校状态。未提供地区时只选全国资料；化学用药指令不进入该观察检索结果。
- 原有50条观察片段与20条农药公告资料继续独立管理。公告范围相符不能证明当前登记有效，规则继续阻止未经核验的剂量、混配、间隔及直接施药许可。
- 案例页可生成、下载JSON及查看可打印报告。快照包含用户事实、症状、模型候选原因、引用、来源时效/变更核对、登记检查、不确定性和下一步。涉及相同对象的多个指导来源要求逐条比较适用条件，不拼接处方。报告只根据已保存案例生成，不冒充本轮尚未完成的观察。
- 复查任务必须绑定当前身份的活动案例并指定明确的未来时间，支持手动设置或智麦 `prepare_followup` 确认卡。无可靠间隔依据时由用户选择时间，不统一安排三天、不自动安排喷药。
- 到点消息回到原案例，可继续补图识别、记录改善/无变化/恶化及实际措施、对照前后观察。恶化标记农技复核，不自动升级药剂；图片角度、光照、拍摄日期差异明确保留。
- 任务改期、暂停、删除、案例关闭及删除都会影响实际执行；发布前再次检查案例归属、状态与任务版本。已提醒、已读与实际复查完成分别记录，不混为一谈。

## 第三步：官方公开情报与地区订阅

入口是“提醒→地区植保订阅”，保留原来四个左侧入口。

- 后台独立线程启动时及每4小时读取农业农村部官方栏目；种子链接和新发现文章经HTTPS白名单、重定向目标、大小与元数据校验后缓存。只有官方文章来源并不能自动取得适用性或农技审校资格。
- 种子链接为真实可访问的2026年春季小麦原文，获取证据见 [来源联通记录](research/official-source-connectivity.json)。它们属于待整理的历史资料，不能当成当前秋季预警。未取得有效情报时显示“当前没有有效情报”，不推送风险结论。
- 新文、变更原文默认待核对。维护人员用本地命令核对类别、地区/城市、对象、有效期与适用说明；没有公开管理员写入接口。技术指导与病虫情报分开，技术指导不直接触发预警。内容变更清除原元数据核对结果，需重新核对。
- 订阅由用户主动确认，可选择省份、城市（可选）、病虫害、每天最多1至3条、北京时间静默时段，随时暂停或取消。市县限定原文只匹配明确选择的相同城市；省级原文保留省级范围，不缩写成用户城市已经发病。
- 仅未过期、非未来发布、24小时内重新获取、适用元数据已核对且地区/对象匹配的病虫情报参与通知。同一用户同一文章跨订阅去重，用户每天频率受限，静默后才处理，过期不补发；没有可靠数据不会从天气或大模型记忆生成预警。
- 每条消息保留来源、发布日期、范围和获取时间，提示是区域巡查信号。通知仍使用现有站内提示与授权桌面通知；关闭网页后的Web Push/微信/短信未接入。

## 本轮没有被软件测试替代的工作

1. 独立农技审校：代码没有把“能打开官网”伪装为“已完成农技审校”。目前用药仍受禁止直接许可的规则保护。需农技人员审定适用观察指导、标签与当前登记状态。
2. 实时地区情报覆盖：当前接入农业农村部栏目及本地维护流程，不声称已覆盖全国植保站所有市县的专报。需要持续维护真正有效的区域情报；无有效资料时保持不提示具体风险。
3. 实机与农户验收：需要真实清晰/模糊图片、至少30个经农技标注的案例及目标手机通知验证。自动化中的30组是工作流回归，不是病害识别准确率评估。模型提示词和自检也不能证明无幻觉。
4. 对外服务：SQLite/浏览器身份适合当前单机部署与受控试用；正式多人长期运行仍需部署、备份、身份管理及真实设备通知渠道验收，不把本次编码等同于已上线。
