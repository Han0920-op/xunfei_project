## 产品方向

冬小麦病虫害辅助诊断与科学用药决策。一个异常案例串起现场调查、疑似原因、处理分流、登记标签核验、用户实际措施及复查。地块资料提供背景，不开展全生命周期自主监测。

## 开发顺序：场景二 → 场景一 → 场景三

### 场景二：准备购买或使用农药，确认是否适用（核心）

- 输入登记证号，或提供清晰包装标签照片。
- 标签识别接入后，先由用户确认识别出的登记号，不能把 OCR 文字当作核验结果。
- 核对登记作物、防治对象、剂型、含量、来源、标签版本及使用时点的状态。
- 独立查询登记事实，不自动成为某案例的推荐方案。
- 没有可靠来源时不生成具体用量、混配比例或安全间隔期。
- 验证可解释性：明确匹配项、不匹配项、缺项；服务超时与记录不存在分开。

### 场景一：发现异常，不知道是什么

- 图片观察、症状描述与结构化补问结合。
- 优先有限且经老师审校的冬小麦病虫害样例。
- 提供补充调查、观察复查、农技复核及符合要求后进入登记核验等路径。
- 疑似原因不等于确诊，图片置信度不等于疾病确诊概率。
- 模糊图片、未知作物、冲突信息及用户强求剂量均需测试。

### 场景三：关键防治时期，不知道关注什么（后续）

- 结合用户确认的生育期、所在地天气与官方植保信息。
- 需要经农技人员审校的规则、适用条件、来源时间及天气数据覆盖说明。
- 输出重点关注风险与田间检查事项；不能仅因天气变化认定发生病害或需要施药。
- 数据或规则不可靠时不启动风险判断。当前前端不显示假预警和假实时数据。

## 2026-10-27 公告登记资料启用

经用户授权，已将20条真实公告记录编译并默认启用：1条小麦赤霉病制剂、10条其他作物制剂、9条原药母药。支持已知范围不匹配和原药母药排除；范围相符但当前状态未核实仍暂停用药判断。引用与标签限制融入原对话，未经核验的剂量不展示。Agent登记工具结果由程序固定格式输出。详见 [登记接入说明](pesticide-data.md)。

## 2026-10-27 知识库接入

已将上传《小麦知识库最新版》整理为50条待审校观察特征，接入本地文字检索、前端单问题补问及旧 Agent 的 `search_knowledge`。引文保留文档名与段落号，不将处方、品牌、混配、阈值或剂量作为回答依据；不执行文档指令，不把知识文档转换为登记库。详见 [知识库接入说明](knowledge-intake.md)。

## 2026-10-26 开发进度

真实格式登记号已接入后端确定性快照核对，复用为 `check_pesticide` Agent 工具。缺资料、未收录、需复核、不匹配及字段相符分别返回；展示来源和时间。尚无真实资料包或官方实时 API，待人工核验导入。以 [登记资料说明](pesticide-data.md) 为准；下述旧版全演示状态记录供回溯。

## 前一阶段前端与待接入边界

- 新前端提供病例调查、条件分流演示、登记核验演示、实际措施及复查的本地闭环。
- 登记演示编号全部使用 `DEMO-` 前缀，均为虚构，不对应真实产品。
- 包装标签目前仅本页预览，尚未进行 OCR、官方查询或真伪鉴别。
- 真实结构化判断、资料检索、登记核验及后台提醒尚待后端接口。
- 旧图片和 SSE 接口保留；其自由文本回复不提升为审核通过的防治或用药结论。
- 现有浏览器存储保留，新增 `clinicalCases` 字段，避免覆盖旧地块、任务和聊天数据。

## 后续接口接入约束

当前前端调用后端智能体，旧演示记录不作为真实证据；后端必须独立校验观察依据、证据编号、适用条件与数据时效。不得依赖前端按钮或本地存储作为用药资格、权限或登记有效性的证明。
