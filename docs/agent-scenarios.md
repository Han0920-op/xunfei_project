# 智麦 V1：场景与开发优先级

依据项目开发路线文档及 2026-10-23 的用户补充讨论。

## 产品方向

冬小麦病虫害辅助诊断与科学用药决策。一个异常案例串起现场调查、疑似原因、处理分流、登记标签核验、用户实际措施及复查。地块资料提供背景，不开展全生命周期自主监测。

## 开发顺序：场景二 → 场景一 → 场景三

### 场景二：准备购买或使用农药，确认是否适用（核心）

- 输入登记证号，或提供清晰包装标签照片。
- 标签识别接入后，先由用户确认识别出的登记号，不能把 OCR 文字当作核验结果。
- 核对登记作物、防治对象、剂型、含量、来源、标签版本及使用时点的状态。
- 独立查询登记事实，不自动成为某案例的推荐方案。
- 没有可靠来源时不生成具体用量、混配比例或安全间隔期。
- 验证可解释性：明确匹配项、不匹配项、缺项；服务超时与记录不存在分开。

### 场景一：发现异常，不知道是什么

- 图片观察、症状描述与结构化补问结合。
- 优先有限且经老师审校的冬小麦病虫害样例。
- 提供补充调查、观察复查、农技复核及符合要求后进入登记核验等路径。
- 疑似原因不等于确诊，图片置信度不等于疾病确诊概率。
- 模糊图片、未知作物、冲突信息及用户强求剂量均需测试。

### 场景三：关键防治时期，不知道关注什么（后续）

- 结合用户确认的生育期、所在地天气与官方植保信息。
- 需要经农技人员审校的规则、适用条件、来源时间及天气数据覆盖说明。
- 输出重点关注风险与田间检查事项；不能仅因天气变化认定发生病害或需要施药。
- 数据或规则不可靠时不启动风险判断。当前前端不显示假预警和假实时数据。

## 当前前端与待接入边界

- 新前端提供病例调查、条件分流演示、登记核验演示、实际措施及复查的本地闭环。
- 登记演示编号全部使用 `DEMO-` 前缀，均为虚构，不对应真实产品。
- 包装标签目前仅本页预览，尚未进行 OCR、官方查询或真伪鉴别。
- 真实结构化判断、资料检索、登记核验及后台提醒尚待后端接口。
- 旧图片和 SSE 接口保留；其自由文本回复不提升为审核通过的防治或用药结论。
- 现有浏览器存储保留，新增 `clinicalCases` 字段，避免覆盖旧地块、任务和聊天数据。

## 后续接口接入约束

前端分支只用于交互演示；后端必须独立校验观察依据、证据编号、适用条件与数据时效。不得依赖前端按钮或本地存储作为用药资格、权限或登记有效性的证明。
