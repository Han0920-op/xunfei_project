# 智麦前端：病虫害辅助诊断与科学用药

原生 HTML / CSS / JavaScript，无需安装 npm 依赖。后端业务代码保持不变。

在仓库根目录启动静态服务：

```sh
python -m http.server 8080 --directory front_end
```

用浏览器打开该静态服务，默认入口 `index.html` 是今日工作台。

## 页面与操作

主导航：诊断工作台、病虫害辅助诊断、科学用药、案例与复查。优先级是登记适用核对 → 异常调查 → 后续关键时期关注。

| 页面                             | 功能                                                           |
| -------------------------------- | -------------------------------------------------------------- |
| `index.html`                     | 登记核验与异常调查入口、待处理案例                             |
| `medication.html?clinicalId=…`   | 登记号输入、包装照片预览、逐项核对演示及案例关联               |
| `diagnosis.html?clinicalId=…`    | 图片观察、现场调查表、未知项、演示分流与可折叠补充对话         |
| `history.html`                   | 新版异常案例列表与筛选                                         |
| `case.html?id=…`                 | 案例概览、调查依据、登记核验记录、实际措施、复查及文字摘要导出 |
| `compare.html?clinicalId=…`      | 案例照片并排／滑动查看、期间措施及人工对比笔记                 |
| `tasks.html`                     | 用户确认的案例复查安排                                         |
| `fields.html`、`field.html?id=…` | 保留地块背景、农事及现场记录                                   |

旧数据未删除：`history.html?source=backend` 保留原诊断历史与实际接口；`tasks.html?source=legacy` 保留原本地任务；`compare.html?fieldId=…` 保留原地块图片对比。

旧链接 `index.html?caseId=…&conversationId=…` 自动转到诊断页并保留参数。新版本地案例用 `clinicalId`，与旧后端整数 `caseId` 分开，防止串用。

## 新版流程边界

- `clinicalCases` 作为新增字段保存在原有本地存储中，不重置旧地块、图片、聊天和任务。
- 登记演示使用 `DEMO-WHEAT-001`、`DEMO-APHID-001`、`DEMO-MISMATCH-001`、`DEMO-INCOMPLETE-001`，全部为虚构编号，不对应真实产品。
- 字段一致也不表示登记有效；未核对真实状态、标签版本和来源前，不提供具体用药数值。
- 包装照片仅预览，未进行 OCR；照片不会自动填充登记号，也不构成官方核验。
- 连接旧后端时，图片描述可用。自由文本模型回复没有结构化审核，界面不将其展示为防治或用药结论；新调查结果显示“待结构化审核”。
- 真实核验服务未接入时明确显示未接入，不请求一个假定存在的接口，也不回退到演示数据。
- 实际措施由用户确认，如实保存；没有真实标签时不判定其合规。复查的改善／加重是用户反馈，不自动归因于药效。
- 归档只改变跟踪状态，不表示治愈。复查提交后本次安排记为已反馈，可再次安排。
- 场景三需经过审核的植保规则与天气／官方信息支持，当前不生成风险预警。

开发参考见 [场景与优先级](../docs/agent-scenarios.md)。

## 演示与后端连接

默认使用**演示模式**，可以独立体验页面。初始地块、任务、天气、照片与回复明确标记为示例；天气不会声称来自实时接口，演示识别也不会声称分析了用户的图片。示例照片来自原仓库，不能作为同一地块连续实拍的证据。

点击顶部“演示模式”或侧栏底部的设置按钮，可切换到**后端连接模式**并填写地址。此模式使用现有 `/vision/upload`、`/chat/stream`、`/conversation/{id}/messages` 和历史案例接口；未新增后端契约。后端需允许前端来源，HTTPS 页面应连接 HTTPS 后端。

图片识别与聊天保持独立：

1. 选择 / 拖入图片只请求图片识别，不发送聊天。
2. 用户发送问题时携带本次有效识别结果。
3. 后续追问使用会话上下文，不重复携带已消费的图片结果。
4. 更换图片会取消旧请求，并丢弃旧结果；识别失败不复用上张图片。
5. 移除图片保留对话；清空会话需明确操作。
6. 正在识别时等待结果或移除图片；正在回复时防止重复发送，可停止接收。
7. 来源不明的工具结果标记为“来源未提供”，不会自动称为实时数据。

## 本地数据范围

地块、新版异常案例、实际措施、复查、核验演示记录、照片记录、任务、对比笔记和演示会话存放在当前浏览器的本地存储中，尚未同步到后端或其他设备。清理浏览器数据会移除这些内容。保存失败时页面会明确提示，不会显示成功。

- 档案照片最大 2 MB；诊断上传最大 4 MB，支持 JPG / PNG / WEBP。
- 本地存储配额有限，照片较多时可能需要改用 IndexedDB 或后端媒体存储，这是后续接入工作。
- “导出文字档案”下载 Markdown，包含基础资料、记录文字和任务；不包含原始照片，请另行保存照片。
- 对比页只整理记录与拍摄条件，不计算虚假的长势评分、病害置信度、产量或品质。
- 任务在页面内管理，浏览器关闭后不会自动调度、推送或调用模型。
- 生长阶段示意不等同于自动生育期识别。

## 验证

```sh
python front_end/tests/browser_smoke.py
```

需要 Python 的 `playwright` 包以及 Chromium；默认浏览器路径 `/usr/bin/chromium`，可通过 `ZHIMAI_CHROMIUM` 指定。测试自行启动临时静态服务。

测试包括桌面 / 平板 / 手机布局、新建与持久化、观察与对比记录、任务完成及恢复、文字导出、图片不自动聊天、失败重试、更换图片的并发响应、聊天上下文、历史恢复、Markdown 转义、UTF-8 / CRLF 流式处理及不完整回复检测。

后端连接模式的浏览器测试使用受控 HTTP 响应，验证请求契约与前端行为；它不代表真实 FastAPI、讯飞或天气接口已通过联调。

## 后续接入

地块 / 种植季 / 任务的数据接口、可靠的后台调度、真实农业知识检索、实际连续采样及品质检测尚未接入。页面已有对应的记录和展示结构，但不会将这些能力标记为已实现。
