# 智麦：面向农户的简洁前端

主导航只有两个入口：**问智麦**和**我的记录**。病虫害提问、手中农药核对、实际处理及复查都围绕同一条对话完成，不要求建立地块档案。

原生 HTML / CSS / JavaScript，无框架和运行时 npm 依赖。在仓库根目录运行：

```sh
python -m http.server 8080 --directory front_end
```

## 用户怎么使用

1. 打开首页，选择照片，或者直接写一句异常描述。**只选照片不会自动发送。**
2. 点击“发给智麦”，每次回答一个问题；可以点选，也可以说“不清楚”。
3. 在同一条记录里点“核对手里的药”，输入登记号并说明准备防治什么。
4. 按实际情况“记下我做了什么”，也可选定复查日期。
5. 从“我的记录”点“来复查”，补上新照片、反馈改善／无变化／加重／说不清楚。

回复优先说明现在能做什么。详细说明折叠展示，不显示置信度、长势评分或未经核实的用药数值。

## 当前是交互演示

本轮不接后端，不调用模型、OCR、农药登记接口和天气服务，也不发送后台通知。照片只是接收、预览与保存，**不会声称识别了用户的图片**。普通登记号显示“未核实”，不推断不存在或适用。

药品核对演示可通过页脚“交互演示，非真实诊断”里的示例入口体验：

- `DEMO-WHEAT-001`：小麦／白粉病字段示例。
- `DEMO-APHID-001`：小麦／蚜虫字段示例。
- `DEMO-MISMATCH-001`：作物／对象不匹配示例。
- `DEMO-INCOMPLETE-001`：信息缺失示例。

这些均为虚构编号，不对应真实产品。即使示例字段相符，仍不提供实际用量、混配或安全间隔期。

## 页面与架构

| 文件              | 职责                                                                 |
| ----------------- | -------------------------------------------------------------------- |
| `index.html`      | 开始提问、单问题补充、用药核对和继续复查                             |
| `history.html`    | 本机记录列表、继续、结束跟踪、移出列表                               |
| `js/main.js`      | 页面、对话、照片交互、简短弹窗和错误反馈                             |
| `js/assistant.js` | 交互服务边界；目前是明确标注的确定性示例，之后替换成已校验的后端响应 |
| `js/store.js`     | 记录保存、旧版数据兼容和 IndexedDB 照片存储                          |
| `js/ui.js`        | 安全的文字显示、图标、提示与对话框                                   |
| `css/app.css`     | 单一响应式样式，无侧栏、无多栏调查表                                 |
| `js/api.js`       | 保留原 API 客户端代码供后续接入；新界面暂不加载或调用                |
| `js/redirect.js`  | 将旧页面链接引导到两个新入口                                         |

原来工作台、地块、用药、病例和对比页对应的大型脚本与样式已移除。旧 HTML 只保留兼容跳转，不再呈现独立功能页面。

## 本地记录与照片

- 保留原存储键 `zhimai.frontend.v1`，新增 `farmerThreads`；旧字段不会被重置。
- 旧 `clinicalCases` 在“我的记录”中按需读取。继续旧记录时，新对话引用旧照片，不复制整段图片数据，也不改写旧原始资料。
- 旧地块、任务、聊天等原始字段仍保留，简洁界面不再逐项展示。服务端历史暂不加载。
- 新照片使用 IndexedDB 单独保存，单张最大 10 MB，支持 JPG / PNG / WEBP；记录内只保存引用，避免把照片塞进 localStorage。
- 清理浏览器数据、更换浏览器、换设备或改变站点来源（含端口）可能无法读取记录。当前不支持云同步。
- 保存失败时保留当前文字及待发送照片，不推进对话，并清理本次未关联成功的照片。
- 不可读取的原有存储不会被空状态覆盖。
- “下载文字摘要”只下载文字，不含照片。重要照片请自行另存。
- “结束跟踪”不等于治愈。复查结果为用户反馈，不等于已确认药效。未提交新照片时不会把旧照片标成“本次”。
- “移出我的记录”移除新版本列表中的条目；旧版原始资料仍保留。照片删除失败可能留下本机孤立文件，当前不承诺永久清除所有历史数据。

## 浏览器验证

```sh
python front_end/tests/browser_smoke.py
```

需要 Python `playwright` 和 Chromium；默认路径 `/usr/bin/chromium`，可用 `ZHIMAI_CHROMIUM` 指定。测试自行启动临时静态服务器，不需要后端、模型或密钥。

验证包括单问题引导、选图不自动发送、照片恢复、错误重试、存储失败保护、旧记录兼容、查药不换页面、标签人工确认、复查图片与反馈、摘要导出、结束跟踪、文字转义及桌面／手机布局。

设计依据及后续接口边界见 [简洁版前端设计](../docs/frontend-simple.md)。
